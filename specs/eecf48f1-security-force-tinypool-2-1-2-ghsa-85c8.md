# Security: force tinypool 2.1.2 (GHSA-85c8-ppgw-ccpr, GHSA-5gmw-xhrv-c9v3)

**Type:** feature

Maintenance only, no behaviour change. tinypool 1.1.1 is not a direct dependency: it is pulled in by vitest@3.2.7 (a dev tool used for tests). It is not listed in package.json or in pnpm-workspace.yaml. The fix is a single new override in pnpm-workspace.yaml, `tinypool@<2.1.2: ^2.1.2`, with a comment naming vitest and the advisory ids. 2.1.2 is the highest patched version named by the three advisories, so it clears all of them. pnpm-lock.yaml must be regenerated with `pnpm install`; it is not hand-edited.

## Acceptance criteria

- **AC-1** Given pnpm-workspace.yaml, when the change is applied, then `overrides:` contains `tinypool@<2.1.2: ^2.1.2` with a comment saying it comes in via vitest and citing GHSA-85c8-ppgw-ccpr and GHSA-5gmw-xhrv-c9v3, in the style of the existing entries.
- **AC-2** Given the change, then package.json, source code, tests and every other entry in pnpm-workspace.yaml are unchanged.
- **AC-3** Given `pnpm install` is run after the change, then pnpm-lock.yaml resolves tinypool only to 2.1.2 or higher within ^2.1.2, and no tinypool 1.1.1 remains.
- **AC-4** Given the updated lockfile, when CI runs migrate, lint, typecheck, test and build, then all pass without edits to tests.

## Edge cases

- vitest 3.2.7 declares tinypool ^1.x; forcing ^2.1.2 is a major bump. If vitest runs fail on it in CI, the fix is to upgrade vitest, which is not part of this change.
- If minimumReleaseAge blocks tinypool@2.1.2 at install time, an exclusion entry may be needed. This is not added now because it is not confirmed.

## Out of scope

- Upgrading vitest or any other package
- Hand-editing pnpm-lock.yaml
- Adding a minimumReleaseAgeExclude entry unless install proves it is needed
- Any behaviour, schema or business-rule change

## Affected areas

- pnpm-workspace.yaml
- pnpm-lock.yaml (regenerated by pnpm install, not hand-written)
