# Security: upgrade next to 16.4.1 (6 advisories)

**Type:** feature

Automated maintenance. Upgrade the direct dependency `next` from 16.3.7 to 16.4.1, the patched version named by the pnpm-audit scan. This clears GHSA-2464-fhr4-w9xw (critical, image optimization RCE), GHSA-673q-mjm6-r5xr (critical, `use cache` RCE), GHSA-cjq9-62q9-8jv4 (high, image optimization SSRF, fixed in 16.3.8) and GHSA-p3m5-59mp-jv5r (high, Server Actions DoS). 16.4.1 is the highest fixed version among them, so one change clears all six. Application behaviour does not change. No business rules are affected.

## Acceptance criteria

- **AC-1** Given package.json, when the change is applied, then `dependencies.next` is exactly "16.4.1" (same exact-pin style as before).
- **AC-2** Given pnpm-workspace.yaml minimumReleaseAgeExclude, when the change is applied, then the pinned entries brought in by next itself (`next`, `@next/env` and every `@next/swc-*` platform package) are changed from 16.3.7 to 16.4.1, and no other entries change.
- **AC-3** Given the repo, when the change is applied, then no `overrides:` entry is added for next (it is a direct dependency) and no other dependency version, source file, test, schema or CI file is changed.
- **AC-4** Given pnpm-lock.yaml, then it is not hand-edited; it must be regenerated by running `pnpm install` (the pull request summary must say so).
- **AC-5** Given the regenerated lockfile, when CI runs migrate, lint, typecheck, test and build, then all pass without edits to tests, unless a test needs a purely mechanical update for the new version.
- **AC-6** Given `pnpm audit --prod` after the lockfile is regenerated, then no advisories remain for next.

## Edge cases

- next is a direct dependency, so an overrides entry would be redundant and is not used.
- The @next/swc-* and @next/env release-age exclusions must match the new version, otherwise pnpm install may refuse the just-released packages.
- A 16.4.x minor bump could surface new lint or type errors; any fix must be mechanical only, and anything larger is reported rather than fixed.

## Out of scope

- eslint-config-next and @next/eslint-plugin-next stay at 16.3.7. They are not affected by the advisories and the request says to change nothing else. Aligning them is left to a follow-up.
- Any other dependency updates or behaviour changes.
- Writing pnpm-lock.yaml by hand.
- Looking up other versions (no network).

## Affected areas

- package.json
- pnpm-workspace.yaml
- pnpm-lock.yaml (regenerated via pnpm install, not by hand)
