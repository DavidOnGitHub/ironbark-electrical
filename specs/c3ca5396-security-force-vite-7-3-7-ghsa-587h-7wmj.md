# Security: force vite 7.3.7 (GHSA-587h-7wmj-h5pm)

**Type:** feature

Automated maintenance. vite is not a direct dependency (not in package.json); it is pulled in transitively by vitest (lockfile has vite@7.3.6). Add one override in pnpm-workspace.yaml forcing vite to the patched 7.3.7, clearing GHSA-587h-7wmj-h5pm (launch-editor existence-check bypass on Windows, high). Application behaviour does not change; vite is only used by the test tooling. No new user stories.

## Acceptance criteria

- **AC-1** Given pnpm-workspace.yaml, when the change is applied, then `overrides:` contains `'vite@<7.3.7': ^7.3.7`, placed in the style of existing entries with a comment: via vitest (GHSA-587h-7wmj-h5pm).
- **AC-2** Given the change, then package.json and every other entry in pnpm-workspace.yaml are unchanged, and no source, test or business doc file is edited.
- **AC-3** Given the change, when `pnpm install` is run to regenerate pnpm-lock.yaml, then vite resolves to 7.3.7 and no vite@7.3.6 remains, so the osv scan reports no vite advisories.
- **AC-4** Given the regenerated lockfile, when CI runs (migrate, lint, typecheck, test, build), then all pass with no test edits and application behaviour is unchanged.

## Edge cases

- 7.3.7 is the highest fixed version named by both findings (same advisory GHSA-587h-7wmj-h5pm), so it clears all of them.
- The override range ^7.3.7 stays within vite 7.x, compatible with vitest's peer range (^5 || ^6 || ^7).
- If minimumReleaseAge blocks 7.3.7 at install time, a minimumReleaseAgeExclude entry for vite@7.3.7 may be needed; not added now as the request says to change nothing else.

## Out of scope

- Hand-editing pnpm-lock.yaml (must be regenerated with pnpm install)
- Upgrading vitest or any other dependency
- Adding a minimumReleaseAgeExclude entry unless install proves it necessary
- Any behaviour, schema, CI or protected-area change

## Affected areas

- pnpm-workspace.yaml (overrides)
- pnpm-lock.yaml (regenerated by pnpm install, not hand-written)
