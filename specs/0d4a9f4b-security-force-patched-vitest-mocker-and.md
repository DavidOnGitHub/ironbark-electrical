# Security: force patched @vitest/mocker and minimatch via overrides

**Type:** feature

Automated security maintenance. Neither package is listed in package.json. @vitest/mocker 3.2.7 is brought in by vitest ^3.2.7 (devDependency). minimatch 10.2.6 is brought in by @typescript-eslint/typescript-estree (via eslint-config-next). So two entries are added under overrides: in pnpm-workspace.yaml, in the style of the existing ones. App behaviour does not change. Only dev/test/lint tooling is affected. No application code, tests, docs or package.json versions change.

## Acceptance criteria

- **AC-1** Given pnpm-workspace.yaml, when read, then overrides: contains `'@vitest/mocker@<4.1.12': ^4.1.12`, with a comment above it saying it comes in via vitest and naming GHSA-82fw-gwwq-j7x9 and GHSA-qxg6-89mg-rqv8.
- **AC-2** Given pnpm-workspace.yaml, when read, then overrides: contains `'minimatch@>=10.0.0 <11.0.1': ^11.0.1`, with a comment above it saying it comes in via @typescript-eslint/typescript-estree (eslint-config-next) and naming GHSA-g3hv-75wg-m249. The minimatch 3.x entries used by eslint plugins are not matched by it and are left alone.
- **AC-3** Given the change, when the diff is reviewed, then only pnpm-workspace.yaml is edited by hand. package.json, application code, tests, docs/business and CI files are unchanged, and pnpm-lock.yaml is not hand-written.
- **AC-4** Given the lockfile is regenerated with `pnpm install`, when `pnpm audit` and the OSV scan run, then GHSA-82fw-gwwq-j7x9, GHSA-qxg6-89mg-rqv8 and GHSA-g3hv-75wg-m249 are no longer reported for @vitest/mocker (resolved 4.1.12 or higher) or minimatch (resolved 11.0.1 or higher).
- **AC-5** Given the regenerated lockfile, when the CI verify job runs migrate, lint, typecheck, test and build, then all pass with no test edits, other than a mechanical update if a new version strictly requires it.

## Edge cases

- Peer compatibility: vitest ^3.2.7 is the parent of @vitest/mocker and would now get a 4.x mocker. The parent may not accept it. If CI fails for this reason, the proper fix is to raise vitest to a patched 4.x. That is not part of this change.
- Major jump for minimatch (10 to 11): the parent, @typescript-eslint/typescript-estree 8.71.0, may use an API or Node range that differs in 11. Lint in CI will show it.
- The existing override 'vite@<7.3.7' and tinypool override stay as they are.
- minimumReleaseAgeExclude: if pnpm refuses 4.1.12 or 11.0.1 as too new, entries for '@vitest/mocker@4.1.12' and 'minimatch@11.0.1' can be added there. Only add them if the install needs them.

## Out of scope

- Upgrading vitest, eslint-config-next or @typescript-eslint packages
- Any behaviour, schema, business-rule or UI change
- Editing tests, CI or other config
- Hand-writing pnpm-lock.yaml (must be regenerated with pnpm install)
- Other audit findings

## Affected areas

- pnpm-workspace.yaml (overrides)
- pnpm-lock.yaml (regenerated by pnpm install, not by hand)
