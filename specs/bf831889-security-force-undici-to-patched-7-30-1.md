# Security: force undici to patched 7.30.1 via override

**Type:** feature

Maintenance only; app behaviour does not change. undici 7.30.0 has 8 findings (4 distinct high-severity advisories: GHSA-2m5v-pch6-74hx, GHSA-4w7w-5xrc-9h26, GHSA-qrxm-fqhp-jwvm, GHSA-xjj6-f33q-929c), all fixed in 7.30.1. undici is not in package.json. It is pulled in transitively by @kabosh-digital/workflow-temporal@0.10.0 (a direct dependency, and also the peer of openai@7.25.0). So a pnpm override is added in pnpm-workspace.yaml, in the style of the existing entries: 'undici@<7.30.1': ^7.30.1, with a comment naming the parent and the advisory ids. 7.30.1 clears all listed advisories; none is left uncleared.

## Acceptance criteria

- **AC-1** Given pnpm-workspace.yaml, when the change is applied, then the overrides block contains exactly one new entry 'undici@<7.30.1': ^7.30.1 with a comment saying it comes via @kabosh-digital/workflow-temporal (and openai peer) and listing GHSA-2m5v-pch6-74hx, GHSA-4w7w-5xrc-9h26, GHSA-qrxm-fqhp-jwvm, GHSA-xjj6-f33q-929c.
- **AC-2** Given package.json, when the change is applied, then it is unchanged (undici is not a direct dependency) and no undici entry is added to minimumReleaseAgeExclude unless pnpm install is otherwise blocked by the release-age rule (assumed not needed since none is pinned today).
- **AC-3** Given the lockfile is regenerated with pnpm install after the change, when it is inspected, then undici resolves to 7.30.1 (or the same ^7.30.1 range's resolved version) everywhere and no undici@7.30.0 remains; the lockfile is not hand-edited in this change.
- **AC-4** Given the updated dependency, when the existing CI verify job (migrate, lint, typecheck, test, build) runs, then it passes with no edits to tests or source code.
- **AC-5** Given a new osv scan after the lockfile is regenerated, then none of the 8 undici findings (GHSA-2m5v-pch6-74hx, GHSA-4w7w-5xrc-9h26, GHSA-qrxm-fqhp-jwvm, GHSA-xjj6-f33q-929c) is reported.

## Edge cases

- The override range ^7.30.1 may resolve to a newer 7.x on regeneration; acceptable as it is in the patched line, and the override matches the style of existing entries.
- If pnpm minimumReleaseAge blocks 7.30.1 at install time, a person should add 'undici@7.30.1' to minimumReleaseAgeExclude; not done preemptively.

## Out of scope

- Any other dependency update
- Changes to package.json, source code, tests, CI or business docs
- Hand-editing pnpm-lock.yaml (must be regenerated with pnpm install)
- Upgrading @kabosh-digital/workflow-temporal or openai
- Pinning any version other than 7.30.1; no network, so no other version was looked up

## Affected areas

- pnpm-workspace.yaml (overrides)
- pnpm-lock.yaml (regenerated by pnpm install, not hand-written)
